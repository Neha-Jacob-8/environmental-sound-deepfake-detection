# Results dashboard

Interactive view of the model results: leaderboard, per-generator EER matrix,
training curves and generator profiles.

## Running it

Two processes. The API first, from the repository root:

```bash
python3 -m src.api.main            # http://127.0.0.1:8000
```

then the frontend:

```bash
cd web
npm install
npm run dev                        # http://localhost:5173
```

Vite proxies `/api` to the backend, so the browser sees one origin and there is
no CORS and no base URL to configure. If the API is not running, the page says
so and offers a retry rather than rendering empty charts.

## No numbers are compiled into this bundle

Every measured value — the leaderboard, per-generator EERs, training curves,
bootstrap intervals, clip counts — is fetched at runtime from `/api/bundle`,
which reads `results/tables/` and `data/metadata/manifest.csv` on each request
(cached on file mtime).

That means **retraining a model changes the site with no rebuild**:

```bash
python3 -m src.training.train --model aasist --epochs 20
python3 -m src.evaluation.compare
# reload the page - the new numbers are there
```

Previously these were constants pasted into the source, which went stale
silently the moment anything was retrained.

`src/data/researchData.ts` still exists but now holds only the palette and the
formatters — design decisions, with nothing to go stale against.

## Verifying provenance

The dashboard is only trustworthy if its numbers trace back to the files the
training runs wrote. That is a command, not a promise:

```bash
python3 -m src.api.verify        # with the API running
```

It reads `results/tables/` and the manifest directly, reads the API, and
compares value by value — 91 of them — exiting non-zero on any mismatch.

The built bundle contains no measured values at all. Confirm it yourself:

```bash
cd web && npm run build
grep -oE "0\.0242|0\.0833|240737" dist/assets/*.js   # no matches
```

Every figure on the page, including the ones quoted inside the findings prose,
is derived from the API response at render time.

## Endpoints

| | |
|---|---|
| `GET /api/bundle` | everything the dashboard needs, one round trip |
| `GET /api/models` | leaderboard rows |
| `GET /api/per-generator` | the 5×7 EER matrix |
| `GET /api/curves` | per-epoch validation EER and training loss |
| `GET /api/confidence` | bootstrap intervals from `bootstrap_ci.csv` |
| `GET /api/generators`, `/api/dataset`, `/api/summary` | metadata |
| `GET /api/embeddings` | 128-d embedding points and the LDA transform |
| `GET /api/audio/{file}` | a bundled test clip |
| `POST /api/predict` | **runs the real detector on uploaded audio** |

`/api/predict` returns `pFake`, the position on the real→seen-fake axis, and the
clip's LDA coordinates, so an uploaded clip can be placed in the same geometry
as the research finding. It resamples and pads or trims to 4.000 s of 16 kHz
mono and reports what it did, so the caller never has to guess what was scored.

## Scope

This covers the **results**. The interactive detector UI, the "can you tell?"
listening challenge and the embedding explorer are specified in
[`docs/ui-prompt.md`](../docs/ui-prompt.md) and are not built here — though the
backend already serves everything they need.

Generated by Google AI Studio from that prompt, then adapted: real title and
research question in place of invented ones, unused AI Studio scaffolding
removed, and the data moved from compiled constants to the API.
